# 実装計画: 体験授業調整アプリ ブラッシュアップ

## 概要
重点4つ: データ壊れにくさ → 案の精度 → 使いやすさ → 見た目。
土台(データ整合)先。精度は `tools/evaluate_plan.py` で毎回数値確認。
現状値(2026-11 実データ): 講師×日×時間帯 37% / +授業 32% / +教室 19%。講師×日固定時 授業65%・教室47%。

## 設計判断
- 開催枠変更時、外れた枠の割り当て = 自動削除 + 状態を draft へ戻す + 画面で件数通知。黙って残すと Must「データ」違反になる(11/29 事例)。
- 設定は「保存値が初期値より優先」維持。代わりに「初期値に戻す」ボタンで解決。DB 移行不要。
- 別名(alias)は teacher / course に列追加。既存 init_schema の列自動追加に乗る。
- 精度改善は1ルールずつ。評価スクリプトで上がった時だけ採用、下がれば戻す。
- 削除系(リセット)は確認モーダル必須。月単位と全体を分ける。

## リスク
| リスク | 影響 | 対策 |
|---|---|---|
| 精度ルール追加で別の月が悪化(過学習) | 中 | 10月・11月の2か月で評価。両方下がらない時だけ採用 |
| 講師×日の決め手がデータにない | 高 | T6 は先生への確認待ち。答え次第で実装/見送り |
| 枠変更時の自動削除で手直し分が消える | 中 | 削除件数を通知、手動行(manual)は削除前に確認モーダル |
| Databricks 上の画面は開発環境から確認不可 | 中 | ローカル SQLite で画面確認、本番はユーザー確認 |
| 系統の自動推定ミス | 低 | 推定は候補表示のみ。確定はユーザー |
